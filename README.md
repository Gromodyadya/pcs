**Тема:** Работа с базами данных. Подключение к SQLite (Flutter, sqflite)

### 1. Цель работы
*   Подключить Flutter-приложение к локальной базе данных SQLite с использованием пакета `sqflite`.
*   Создать таблицы и реализовать базовые операции CRUD (создание, чтение, обновление, удаление).
*   Настроить класс-помощник (DBHelper) для отделения логики работы с данными от интерфейса (UI).
*   Изучить механизмы миграции схем и обработки асинхронных запросов к БД.

### 2. Ход работы

#### Шаг 1. Подготовка и зависимости
В файле `pubspec.yaml` были добавлены необходимые библиотеки для работы с путями, директориями и самой базой данных:
```yaml
dependencies:
  sqflite: ^2.3.3
  path: ^1.9.0
  path_provider: ^2.1.4
```

#### Шаг 2. Разработка модели данных
Был создан класс `Note`, описывающий сущность заметки. Реализованы методы `toMap()` и `fromMap()` для преобразования данных между объектами Dart и форматом, который понимает SQLite.
```dart
// Ключевой фрагмент: конвертация даты в миллисекунды для хранения в БД
'created_at': createdAt.millisecondsSinceEpoch,
```

#### Шаг 3. Создание класса DBHelper
Реализован паттерн «Одиночка» (Singleton) для управления подключением к БД. В методе `onCreate` прописан SQL-запрос для создания таблицы и индекса для быстрой сортировки.
```dart
static Future<Database> _open() async {
  final docs = await getApplicationDocumentsDirectory();
  final dbPath = p.join(docs.path, 'app.db');
  return await openDatabase(dbPath, version: 1, onCreate: ...);
}
```

#### Шаг 4. Разработка пользовательского интерфейса
Интерфейс построен на виджете `FutureBuilder`, который автоматически обновляет список при получении данных из БД. Реализованы диалоговые окна для ввода текста и механизм `Dismissible` для удаления заметок свайпом.

### 3. Техническое описание реализации

**Где хранится файл БД:**
Файл базы данных с именем `app.db` хранится во внутренней директории песочницы приложения (Internal Storage). Доступ к этой папке осуществляется через метод `getApplicationDocumentsDirectory()` библиотеки `path_provider`. На телефоне путь выглядит примерно так: `/data/user/0/com.example.notes_sqlite_app/app_flutter/app.db`.

**Устройство таблицы и индексов:**
В приложении используется одна основная таблица `notes`:
*   `id`: `INTEGER PRIMARY KEY AUTOINCREMENT` — уникальный идентификатор.
*   `title`, `body`: `TEXT NOT NULL` — заголовок и содержание заметки.
*   `created_at`, `updated_at`: `INTEGER NOT NULL` — временные метки (Unix Time в миллисекундах).
Для оптимизации производительности создан индекс `idx_notes_created_at` на поле `created_at`. Это позволяет мгновенно получать отсортированный по дате список заметок даже при большом их количестве.

**Реализация CRUD:**
Все операции выполняются асинхронно (`Future`):
1.  **Create (C):** Метод `db.insert()` принимает карту (Map) и возвращает ID новой строки.
2.  **Read (R):** Метод `db.query()` выполняет SELECT запрос. Результаты (список Map) трансформируются в объекты `Note` с помощью фабричного конструктора.
3.  **Update (U):** Метод `db.update()` обновляет запись, используя `whereArgs` для защиты от SQL-инъекций.
4.  **Delete (D):** Метод `db.delete()` удаляет запись по ID.

### 5. Проблемы и решения

В ходе выполнения работы возникла ошибка **"setState() callback returned a Future"**.
*   **Причина:** При использовании стрелочной функции в `setState(() => _future = DBHelper.fetchNotes())` функция неявно возвращала объект `Future`, что запрещено правилами Flutter.
*   **Решение:** Синтаксис был заменен на блок с фигурными скобками:
    ```dart
    setState(() {
      _future = DBHelper.fetchNotes();
    });
    ```
Это позволило функции возвращать `void`, сохранив при этом обновление состояния.
